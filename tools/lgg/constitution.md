# LGG 总则

先发布 site 场地框，再发布 coarse 模块框，最后逐个 module 细化。不要等所有细节设计完再交稿。自然语言需求由模型转成模块与参数，构造器负责几何，不把需求字符串当作固定场景开关。

草稿使用米、Z-up、世界坐标中心、完整尺寸。ID 来自 scene、area、module 和构造器固定编号；调整尺寸不能改模块 ID。每次修改序号加一；同一稿重复发送必须保持正文一致。

保持入口可达，围合至少留一面开放；地面贴合场地，门洞默认净宽 2 m、净高 2.4 m；台阶高度不超过 0.4 m。3C 可达性完整检查属于后续阶段，不得声称已经验证通关。

init 已返回 schema，无需重复读取相同帮助。草稿不产生正式实体；lgg_run play 才调和提交。它立即返回施工请求，允许用户继续输入。status 中 commit.status=applied 才表示正式提交成功，presentation.state=completed 才表示镜头已经交还。不能把 scheduled 说成完成。

修改施工中的模块时发布下一版 module 并 play。旧预览和旧待执行提交会取消，实体无需回滚。已经提交的实体保留到新提交完成；不能通过重新 init 伪装撤销。报错要说明 warnings；不直接写 SQLite 或引擎对象。
