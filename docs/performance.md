# 性能与工程验证记录

所有数字来自开发机的真实 Shipping 包与回环 HTTP 测试，包含不同版本、不同场景与不同硬件条件。它们用于说明量级和回归趋势，不是横向基准。

## 方法

- **离线**：pytest 使用 fake app-server / CLI 与内存替身，不调用真实模型。
- **运行时**：Shipping 包以 Standalone 运行，Python 或测试脚本通过回环 HTTP 驱动，游戏线程计时单独记录。
- **三个时钟**：TTFV（对话到首帧可见）、提交完成、演出完成分别统计，不用一个数字概括全部。
- **延迟与 soak**：`tests/latency/` 与 `tests/run_soak.py` 是可重复的驱动脚本，输出 p50/p95 与帧分布。

## 快速构建：为什么值得做

旧流程（`lgg_card` → `lgg_draft` → `lgg_run`）在一次便利店任务中花了 **187.63 s** 对话时间，92 次工具调用只占 2.98 s，真正开始建造已是第 182.70 s。瓶颈不在世界写入，而在让模型分多次推理同一份结构。

新的 `lgg_build(plan, request_id)` 把完整计划一次编译：

| 任务 | 实体数 | p50 | p95 |
|---|---:|---:|---:|
| 便利店 | 144 | 19.57 s | 25.69 s |
| 展厅 | 146 | 15.50 s | 19.24 s |
| 庭院 | 133 | 10.80 s | 12.21 s |

总体 p50 15.50 s、p95 22.36 s。**p95 ≤10 s 的目标没有达到**——记录里如实写了这一点，而不是只报均值。

## 分帧预算

引擎侧约束是单批 ≤16,384 实体、每帧应用 ≤2 ms。实际测量中：

- 快速构建最大单帧应用 1.10 ms；
- 向上生长最大单实体应用 1.103 ms；
- 10k 场景单实体应用最大 4.92 ms，属于超预算个案，已被记录为待优化项；
- 30 分钟 soak 中 frame p95 8.18 ms，所有帧低于 100 ms。

## 演出与音频

- 短演出只在"首次完整新建结构"时播放 4 s，扩展时 3 s，明确要求展示时 5 s；编辑与无变化不自动播放。
- 向上生长使用一个共享的显现区间，不做逐件排序；镜头按总览、逐模块、主机位编排。
- 原创配乐的节拍来自实际 PCM 瞬态分析并量化到节拍网格，误差最大 6.71 ms（80 ms 校准后）。

## 复现方式

```powershell
# 离线
$env:PYTHONPATH="$PWD\tools"
.venv\Scripts\python -m pytest -q -m "not live"

# 需要可丢弃运行时的基准
.venv\Scripts\python tests\latency\run_w1.py
.venv\Scripts\python tests\run_soak.py
```

仓库不附带游戏构建与模型凭据；运行时类基准需要在具备 UE 5.8 工程与本机 Agent 的环境中执行。
