# 语义核心（协议 4）

协议 4 是协议 3 的**增量扩展**：原有的实体、事务与演出语义不变，新增一层稳定的语义身份与结构化查询，让 Agent 不再依赖截图或 Actor 名来理解场景。

## 为什么需要它

Agent 面对一个 300 个以上实体的场景时，纯视觉和"读所有对象"都不可行：Actor 名会在重建后漂移，截图有遮挡与投影歧义，全量读取既慢又超出上下文。语义核心要解决三件事：

1. **身份**：用户说"刚才那根柱子"，系统要能命中同一个持久实体。
2. **查询**：按角色、区域、包围盒、邻近关系筛选，结果可分页、可计数、可摘要。
3. **变更**：Agent 只取自己上次看到的增量，断线或重启后能判断是否需要重新同步。

## 身份模型

`ULCIdentityComponent` 由作者声明，包含持久 `PersistentId`、显示名、角色、别名、区域、ISM 实例级身份与状态字典。持久 ID 不由 Actor 名派生——Actor 名、指针和索引绝不跨层暴露。

提交时身份写入 SQLite；运行时观测（位置、包围盒、可见性等）单独采样。查询在"已提交身份"与"当前观测"之间做一致性检查，并用叶节点指纹检测实体是否被替换。

## `lc.query` 契约

| 输入 | 说明 |
|---|---|
| `ids` / `name` | 精确身份或显示名 |
| `role` / `source` / `area` / `pattern` / `ring` / `side` | 语义筛选 |
| `within` / `parent` / `bounds` / `near` / `relation` | 空间筛选与关系 |
| `order` | `id` / `view_left` / `distance` |
| `ordinal` | 在有序结果中取第 N 个 |
| `limit` / `cursor` | 默认 32，最大 256，游标分页 |
| `fields` | 返回字段裁剪 |
| `mode` | `list` / `count` / `summary` |
| `state` | `committed` / `live` |

`view_left` 会把查询瞬间的玩家镜头冻结为空间参照；投影歧义或候选被遮挡时返回 `ambiguous`，并且**不能生成写令牌**。这说明系统宁可拒绝，也不猜用户指的是哪一个。

## 选择令牌与写安全

查询结果中的 `selection_id` 固定实体 ID、世界版本与叶节点指纹，有效期 120 秒；服务端缓存最近 256 个选择与 16 个分页游标。写操作必须携带有效令牌，因此：

- 世界在查询后发生变化，旧令牌失效；
- Agent 不能拿旧结果去写一个已经被替换的实体；
- 过期后必须重新查询，而不是重试写。

## 增量与恢复

`lc.changes` 返回两个独立游标：持久事务游标与实时状态游标。重启、过期或游标不连续时返回 `resync_required`，客户端必须重新查询，而不是假定"没有变化"。

`lc.annotate` 在事务内写入别名与语义元数据，可撤销、可持久化；它不修改几何，也不改变实体身份。

## 知识检索

`lgg_knowledge` 从六个配对的 LGG / 白盒案例中检索设计参考，不依赖模型或向量服务。案例带审核状态：候选案例会明确标注"未经人工审核"，不会被当作已验证结论。

## 10k 实体实测

| 指标 | 结果 |
|---|---|
| 5 × 2,000 实体构建 | 总计 28.98 s（版本 5–9） |
| 每次提交 `commit_observed` | 2,000 实体 2.75 s → 10,000 实体 7.83 s |
| 编辑帧 | 293 样本，p50 6.62 ms / p95 13.37 ms / max 297.76 ms |
| 单实体应用 | 最大 4.92 ms |
| `summary` 查询 | 100.5 ms / 671 B |
| `count` 查询 | 79.7 ms / 369 B |
| 全量分页 | 40 页，聚合 357.8 ms / 1.264 s 墙钟 / 4.23 MB |
| 一致性 | 10,552 注册 / 10,542 持久 / 10,533 内存-实例，`consistency: ok` |

297.76 ms 的尖峰出现在提交与持久化发布阶段，不在逐实体应用路径上。

## 已知缺口（尚未 GA）

- 实体注册/移除是 O(n²)，每次提交做全量重排与全表删除；10k 提交成本需要索引化。
- ISM 卸载/重载后的初始索引重排映射尚未复验，可能错配持久 ID。
- `identities` / `identity_*` 表目前只写不读，`semantic_invalidated` 会枚举全部节点，constraints 只存不暴露。
- 六个知识案例仍待人工审核。

这些缺口不影响协议 4 在 10k 实体内的功能性验证，但足以阻止把它标记为 GA。
